# 4.100.0

## Uploads on Node.js 26, Bun and Deno

Uploads were broken in Telegraf 4.16.3, and were rewritten for this release. They now work on Node, Bun, and Deno.

The rewrite fixes a few long-standing problems on every runtime:

- Files are now streamed. 4.16.3 read a whole stream into memory before sending any of it.
- A file is uploaded wherever it is in a payload. 4.16.3 only looked at top-level fields and inside media items, so calls like these two were sent without their file and failed:

  ```TS
  // a thumbnail beside a file_id
  await ctx.telegram.sendMediaGroup(chatId, [
    {
      type: "video",
      media: fileId,
      thumbnail: InputFile.fromLocalFile("cover.jpg"),
    },
  ]);

  // the sticker of an input sticker
  await ctx.telegram.addStickerToSet(userId, "set_by_bot", {
    sticker: {
      sticker: InputFile.fromLocalFile("sticker.webp"),
      format: "static",
      emoji_list: ["👍"],
    },
  });
  ```

- `reply_parameters` is no longer lost on uploads ([#2095](https://github.com/telegraf/telegraf/pull/2095)). 4.16.3 only sent a fixed list of objects beside a file and dropped the rest. With `useNewReplies()`, a `ctx.replyWith*` upload now replies to the message, as text always did.
- Various other upload-related bugs were found and squashed.

## The `fetch` option

Telegraf can now send its requests through a `fetch` you provide: the global fetch from Node.js, Bun or Deno, undici's, or your own wrapper around one.

```TS
const bot = new Telegraf(token, { fetch });
```

A wrapper gives you control over the connection, which is how you set up a proxy or your own timeouts:

```TS
import { Agent, fetch } from "undici";

const dispatcher = new Agent({ connect: { timeout: 10_000 } });

const bot = new Telegraf(token, {
  fetch: (url, init) => fetch(url, { ...init, dispatcher }),
});
```

This is opt-in. Without the option requests are still sent with `node-fetch`. Using the platform `fetch` will become the default in the next major version (soon!), so it's good to start passing it now. A few things to remember when you pass `fetch`:

- `telegram.agent` and `telegram.attachmentAgent` are ignored, with a warning. Configure the connection in the `fetch` you pass.
- A wrapper must pass `init.signal` on to the underlying fetch. Aborting a call, `bot.stop()` and timeouts depend on it.
- The same `fetch` downloads the URLs of `InputFile`s, so headers added by a wrapper also go to those hosts.
- `node-fetch` 2 is not accepted as a `fetch`, since it can't send a stream. A standard `fetch` implementation is required.

## `InputFile`

`InputFile` uploads a file in any form, accepting more input types than before:

```TS
import { InputFile } from "telegraf";

await ctx.replyWithDocument(InputFile.fromLocalFile("report.pdf"));
await ctx.replyWithPhoto(InputFile.fromURLStream("https://example.com/cat.jpg"));
await ctx.replyWithVoice(new InputFile(buffer, "note.ogg"));
await ctx.replyWithDocument(new InputFile(await fetch(url)));
```

| file                                                               | `InputFile`                     | uploaded                                |
| ------------------------------------------------------------------ | ------------------------------- | --------------------------------------- |
| a local path                                                       | `InputFile.fromLocalFile(path)` | the file at that path                   |
| an `http://` or `https://` URL                                     | `InputFile.fromURLStream(url)`  | downloaded (streamed) by Telegraf       |
| a `Buffer`, `Uint8Array`, `ArrayBuffer`, `Blob` or `File`          | `new InputFile(source)`         | as it is                                |
| a Node.js stream, a web stream, an async iterable or a `Response`  | `new InputFile(source)`         | read once                               |
| a function that returns an `InputFile`, a `URL`, or a source above | `new InputFile(source)`         | called when the upload reaches the file |

The filename is inferred from its path, the last segment of its URL, or the name of a `File`, unless you name it in the second argument. A URL segment without an extension gets the one of its parameter: `https://example.com/render?id=7` sent as an animation is named `render.mp4`.

A `file_id`, or a URL for Telegram to download itself, is still passed as a plain string.

Prefer a function for anything that comes from the network. It gets a signal that aborts when the call ends:

```TS
await ctx.replyWithDocument(new InputFile((signal) => fetch(url, { signal })));
```

A stream that is already open has to wait for the files before it in the same call, and its host may have closed it by then. A function is called when the upload reaches the file, and again in every call that sends it, so the same payload can be retried. An `InputFile` made from a stream can be sent once.

## Deprecating `Input` and plain file objects for `InputFile`

Passing a file as a plain object, like `{ source: "photo.jpg" }` or `{ url }`, is deprecated. Your bots continue to work, but each kind of plain object now prints a `DeprecationWarning`, once. The `Input` helpers are deprecated too, with no warning. Use `InputFile` instead:

```diff
- await ctx.replyWithPhoto({ source: "photo.jpg" });
- await ctx.replyWithPhoto(Input.fromLocalFile("photo.jpg"));
+ await ctx.replyWithPhoto(InputFile.fromLocalFile("photo.jpg"));
```

| deprecated                                               | replacement                     |
| -------------------------------------------------------- | ------------------------------- |
| `{ source: path }`, `Input.fromLocalFile(path)`          | `InputFile.fromLocalFile(path)` |
| `{ source: buffer }`, `Input.fromBuffer(buffer)`         | `new InputFile(buffer)`         |
| `{ source: stream }`, `Input.fromReadableStream(stream)` | `new InputFile(stream)`         |
| `{ url }`, `Input.fromURLStream(url)`                    | `InputFile.fromURLStream(url)`  |
| `Input.fromURL(url)`, `Input.fromFileId(fileId)`         | the string directly             |

A copy of an `Input` helper's result, such as a spread or a `structuredClone`, counts as a plain object. Plain objects and the `Input` helpers will be removed in v6.

An `InputFile` accepts several new input types, such as web streams and Blobs. Code that narrows a file by `'url' in file` or `typeof file.source` now has to handle these as well.

## Deprecating the `telegram` option

`fetch` is now a direct option of `Telegraf`, and the options that were inside `telegram` are now outside it:

```diff
  const bot = new Telegraf(token, {
-   telegram: { apiRoot: "http://localhost:8081", webhookReply: false },
+   api: { root: "http://localhost:8081" },
+   webhookReply: false,
  });
```

| in `telegram`              | option                              |
| -------------------------- | ----------------------------------- |
| `apiRoot`                  | `api.root`                          |
| `apiMode`                  | `api.mode`                          |
| `testEnv: true`            | `api.environment: "test"`           |
| `webhookReply`             | `webhookReply`                      |
| `agent`, `attachmentAgent` | configure the connection in `fetch` |

Your bots continue to work, but passing `telegram` now prints a `DeprecationWarning`. It will not be accepted in v6. `new Telegram(token, options)` takes the same `fetch`, `api` and `webhookReply`, and its old option names are deprecated as well.

## Other fixes and improvements

- `bot.launch()` no longer rejects with `TypeError: Attempted to assign to readonly property` when a bot on Bun is stopped ([#2078](https://github.com/telegraf/telegraf/issues/2078)).
- Long polling retries a failed request whatever its error. 4.16.3 only retried a `FetchError`, which Bun never throws, so one dropped connection ended polling there.
- `bot.stop()` no longer waits out the pause before a polling retry.
- The secret part of the bot token is replaced with `[REDACTED]` in the message, the stack and the cause of an error, as in `bot123456:[REDACTED]`. 4.16.3 redacted errors the same way, but missed some.
- A `{ url }` file whose host answers with an error status fails the call. 4.16.3 uploaded the error page.
- `sendVideoNote` and `replyWithVideoNote` accept every kind of file, including one that Telegraf downloads from a URL. 4.16.3's types refused `{ url }` there, and also the results of `Input.fromLocalFile`, `fromBuffer` and `fromReadableStream`, which were typed as any kind of file. `InputFileVideoNote` is deprecated: it is now the same type as `InputFile`.

## Minor breaking changes

- (Breaking) Node.js 20 or later is required. 4.16.3 accepted `^12.20.0 || >=14.13.1`.
- (Breaking) A file object is exactly `{ source, filename? }` or `{ url, filename? }`. An object with any other key is not a file. 4.16.3 ignored the other key and uploaded it; the call now rejects with `TypeError: Invalid file under ...` when its `source` holds the contents of a file, such as a Buffer or a stream.
- (Breaking) `thumb` in a media item is no longer also sent as `thumbnail`. Use `thumbnail`, the name the Bot API has used since 6.6.
