# v6.0.0

This is an unreleased v6 candidate; the official npm package has not yet been
updated to this version.

## Bot API 10.3 support

- Added support for [Telegram Bot API 10.3](https://core.telegram.org/bots/api).
- Updated TypeScript declarations through the companion `@telegraf/types` 10.3 PR,
  using upstream's unified declaration layout and compatibility exports.
- Added coverage for Bot API additions introduced after the last v4 API sync, including:
  - managed bots;
  - message drafts;
  - chat member tags and related permissions;
  - profile photo methods for bots and business accounts;
  - newer business account, gift, and star methods;
  - multiple-correct-answer polls;
  - persistent poll option identifiers;
  - poll option add/delete service messages;
  - reply-to-poll-option fields.
- Added Bot API 10.x rich messages and drafts, live photos, guest queries,
  ephemeral messages, join request queries, media in polls, and reaction
  management. Context getters and `useNewReplies()` support the new payloads
  where applicable.

## Complete runtime method coverage

- `Telegram` now exposes a wrapper for all 185 official Bot API methods.
- Newer Bot API methods use raw object-style calls, matching Telegram's request shape:

  ```ts
  await ctx.telegram.sendChecklist({
    business_connection_id,
    chat_id,
    checklist,
  })
  ```

- Existing positional helpers remain where Telegraf already had stable patterns.
- `getChatMemberCount` is now available while the legacy `getChatMembersCount`
  wrapper remains for compatibility.

## Multipart uploads

- Multipart request building now detects `InputFile` values recursively inside
  arrays and objects.
- Nested files are uploaded as separate multipart parts and replaced with
  `attach://...` references in the JSON payload.
- This enables modern nested media payloads such as profile photos, story
  content, paid media thumbnails, and other newer Bot API objects.
- Integrated upstream's async-generator multipart stream implementation and
  removed `sandwich-stream`. Backpressure is handled by Node.js streams.
- Interrupted uploads and attachment assembly failures close already-opened
  sources, including queued files. Source errors abort the outgoing request.

## Runtime robustness

- Long polling can optionally retry transient `409 Conflict` startup races with
  `launch({ polling: { retryOnConflict: true } })`.
- `launch` callbacks now run after polling or webhook startup state is
  initialized, so immediate `bot.stop()` calls no longer race the startup
  window.
- Bot API request timeout is configurable with
  `telegram: { requestTimeout: ms }`; use `0` or `Infinity` to disable it.
- Timeouts also cover response-body consumption. Polling retry backoff is
  cancelled immediately by `stop()`, and unexpected aborts are not swallowed.
- Bot API transport failures now throw `TelegrafNetworkError`, with a sanitized
  `cause`, `errorName`, `code`, and `transient` flag. The original native error
  is never mutated. `TelegramError` continues to represent API/HTTP failures;
  both extend the public `TelegrafError` base class.
- The default network client now uses the Node.js native `globalThis.fetch`.
- `node-fetch` is no longer bundled by Telegraf. If you need proxy agents,
  custom TLS handling, custom compression, or another non-standard network
  path, install your preferred fetch implementation and pass it as
  `telegram.fetch`.
- The old `agent` and `attachmentAgent` options were removed with the
  `node-fetch` dependency. Custom networking should now be implemented inside
  the injected `telegram.fetch` function.
- `session()` now defaults missing sessions to an empty object, removing the
  most common first-use footgun while still allowing explicit `defaultSession`
  values.
- Scene typings now export `SceneOptions`, allow subclass access to
  `SceneContextScene` internals through `protected` fields, and infer
  `ctx.scene.state` from custom scene session data.

## Compatibility

- Requires Node.js 22.20 or later, matching the current AVA 8 development
  baseline. Node 20 is no longer supported; upstream CI also targets 22-26.
- Most existing v4 middleware, context, session, scene, webhook, and formatting
  patterns remain the intended migration path.
- Bot API 10.x contracts follow the current official definitions: ephemeral
  message and receiver identifiers are numeric, guest answers use
  `InlineQueryResult`, `sendLivePhoto` uses `photo` and `live_photo`, and thinking
  blocks are draft-only. TypeScript checks reject obsolete payload forms.
- TypeScript rejects `InputFile` uploads in rich-message drafts and inline
  edits, including URL-backed uploads. Existing file IDs remain supported. Chat and ephemeral
  edits still allow uploads. For `ctx.editMessageText`, narrow the Context to
  a non-inline update or use explicit chat/message IDs with
  `telegram.editMessageText` before uploading. Plain strings are not branded
  file IDs: callers must still avoid explicit URL uploads in restricted paths.
- Until [the types PR](https://github.com/telegraf/types/pull/14) is published,
  this branch pins `@telegraf/types` to HTTPS commit
  `88aa916e2ef6efe851da244f23d5532ef1526738` in `Leask/types`. Git is required;
  SSH credentials are not. Switch to the official 10.3 registry package before
  an upstream release. This replaces the previous 9.6 npm alias.

## Tooling and maintenance

- Updated dependencies and CI actions for the v6 line.
- Updated the network client for native fetch and `p-timeout` 7 compatibility.
- Migrated linting to ESLint 9 flat config.
- Updated TypeDoc configuration for the current TypeDoc release.
- Added API coverage tests to keep runtime wrappers aligned with
  an independent official 10.3 method snapshot and `@telegraf/types`.
- Added compile-time positive/negative contracts and loopback HTTP tests for
  new payloads, multipart cleanup, cancellation, and the network error boundary.
- CI installs from the lockfile and runs tests and lint on Node 22.20, 24.12, and 26.
