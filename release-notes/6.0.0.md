# v6.0.0

## Bot API 9.6 support

- Added support for the current [Telegram Bot API 9.6](https://core.telegram.org/bots/api).
- Updated TypeScript declarations through `@telegraf/types` 9.6.
- Added coverage for Bot API additions introduced after the last v4 API sync, including:
  - managed bots;
  - message drafts;
  - chat member tags and related permissions;
  - profile photo methods for bots and business accounts;
  - newer business account, gift, and star methods;
  - multiple-correct-answer polls;
  - persistent poll option identifiers;
  - poll option add/delete service messages;
  - reply-to-poll-option fields.

## Complete runtime method coverage

- `Telegram` now exposes a wrapper for every typed official Bot API method.
- Newer Bot API methods use raw object-style calls, matching Telegram's request shape:

  ```ts
  await ctx.telegram.sendChecklist({
    business_connection_id,
    chat_id,
    checklist,
  })
  ```

- Existing positional helpers remain where Telegraf already had stable patterns.
- `getChatMemberCount` is now available while the legacy `getChatMembersCount`
  wrapper remains for compatibility.

## Multipart uploads

- Multipart request building now detects `InputFile` values recursively inside
  arrays and objects.
- Nested files are uploaded as separate multipart parts and replaced with
  `attach://...` references in the JSON payload.
- This enables modern nested media payloads such as profile photos, story
  content, paid media thumbnails, and other newer Bot API objects.

## Runtime robustness

- Long polling can optionally retry transient `409 Conflict` startup races with
  `launch({ polling: { retryOnConflict: true } })`.
- `launch` callbacks now run after polling or webhook startup state is
  initialized, so immediate `bot.stop()` calls no longer race the startup
  window.
- Bot API request timeout is configurable with
  `telegram: { requestTimeout: ms }`; use `0` or `Infinity` to disable it.
- Advanced users can provide a custom `telegram.fetch` implementation for Bot
  API requests and URL attachments.
- `session()` now defaults missing sessions to an empty object, removing the
  most common first-use footgun while still allowing explicit `defaultSession`
  values.
- Scene typings now export `SceneOptions`, allow subclass access to
  `SceneContextScene` internals through `protected` fields, and infer
  `ctx.scene.state` from custom scene session data.

## Compatibility

- Dropped support for Node.js versions below 20.
- Most existing v4 middleware, context, session, scene, webhook, and formatting
  patterns remain the intended migration path.
- Until the Bot API 9.6 update is published by upstream `telegraf/types`, this
  branch temporarily depends on
  `git+https://github.com/Leask/types.git#bot-api-9.6-sync`.

## Tooling and maintenance

- Updated dependencies and CI actions for the v6 line.
- Updated the network client for `node-fetch` 3 and `p-timeout` 7 compatibility.
- Migrated linting to ESLint 9 flat config.
- Updated TypeDoc configuration for the current TypeDoc release.
- Added API coverage tests to keep runtime wrappers aligned with
  `@telegraf/types`.
